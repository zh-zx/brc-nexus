# BRC Nexus v2 操作说明

> 种质资源标签打印系统 · CIP-CCCAP
> 版本：2.8.0 · 2026-08-26

---

## 一、这是什么系统？

一个**局域网内的种质标签打印工具**，包含：
- 从 Excel 导入种质数据
- 浏览、搜索种质信息
- 拖拽设计标签模板
- 扫码打印热敏标签（手机 / 平板 / PC 都能用）
- 简单的库存管理（试管、房间）

**底层数据库**是 `server/data/brc.db`（SQLite 格式，标准文件），可以直接用 [DB Browser for SQLite](https://sqlitebrowser.org/dl/) 打开查看。

## 二、快速开始（5 分钟）

### 1. 启动服务器

在 Windows 上打开命令行（PowerShell 或 cmd），执行：

```bash
cd C:\Users\Lenovo\brc-helper-v2\server
node src\index.js
```

看到以下输出即启动成功：
```
========================================
  BRC Nexus v2 Server
  Local:    http://localhost:7800
  LAN:      http://<your-ip>:7800
========================================
```

**注意**：这个窗口不能关，关了服务就停了。

### 2. 打开浏览器访问

- 本机：http://localhost:7800
- 局域网其他设备：http://你的IP地址:7800
  - 查看 IP：在 cmd 里运行 `ipconfig`，看 "IPv4 地址" 那一行
  - 例如：http://192.168.1.100:7800

### 3. 创建管理员账号（首次使用）

第一次打开会进入设置页面，填写：
- 用户名：随便起，例如 `admin`
- 密码：至少 6 位
- 显示名称：例如「管理员」

点击「创建管理员」即可。

### 4. 登录

之后每次打开都会看到登录页，输入刚才的用户名和密码。

## 三、导入数据（重要！）

**数据库默认是空的**，必须先导入 Excel 才能用。

### 步骤

1. 登录后，点左侧 **「系统设置」**
2. 找到 **「数据导入」** 区块
3. 点击上传区域，选择你的 Excel 文件（.xlsx 或 .xls）
4. 系统会自动检测列对应关系：
   - `cccap` / `id` / `编号` → 识别为种质编号
   - `name` / `名称` / `品种` → 识别为品种名
   - `species` / `物种` / `学名` → 识别为物种
   - `origin` / `来源` / `原产` → 识别为来源地
5. 如果识别错了，手动调整下拉框
6. 选择导入模式：
   - **覆盖**（Replace）：相同编号的记录会被新数据覆盖
   - **跳过**（Skip）：已存在的记录保持不变
   - **合并**（Merge）：只更新空字段，保留已有数据
7. 点 **「Import」** 按钮

### Excel 文件要求

- 第一行必须是列标题（表头）
- 每行一条种质记录
- 至少有一列是唯一的种质编号

**示例格式**：

| cccapNo | name | species | origin |
|---------|------|---------|--------|
| CIP-001 | Russet Burbank | Solanum tuberosum | USA |
| CIP-002 | Atlantic | Solanum tuberosum | Canada |
| CIP-003 | 龙薯 9 号 | Ipomoea batatas | China |

## 六、打印标签（接热敏打印机）

### 原理（v2.1 起为「所见即所得」）

在标签设计页设计的模板，会**原样**生成打印用的 HTML（`labelsHtml`）交给打印代理，打印代理用 Electron 把它渲染到打印机 —— **设计器里看到什么，打印出来就是什么**。旧版基于文本 + 二维码的打印方式作为兜底保留，仅在模板没有 WYSIWYG 数据时启用。

服务器通过 WebSocket 向**打印代理**（print-agent）发送任务，打印代理在连接打印机的 Windows PC 上运行，控制打印机输出。

### 步骤

1. **在接打印机的电脑上**打开新命令行：
   ```bash
   cd C:\Users\Lenovo\brc-helper-v2\print-agent
   npm install
   npm start
   ```
2. 打印代理会自动连接 `http://localhost:7800/ws/print-agent`
3. 如果服务器在其他机器上，需要修改 print-agent 的连接地址（见 print-agent/README）

### 不装打印代理可以吗？
可以，但只能：
- 在浏览器里**预览**标签效果
- 用浏览器自带的打印功能打印到普通打印机（PDF）

真正的热敏标签打印机必须装打印代理。

## 八、常见问题

### 1. 忘记密码怎么办？
删除 `server/data/brc.db` 文件，重启服务器，重新创建管理员账号。
**注意**：这会删除所有数据！提前备份。

### 2. 服务器启动报错「EADDRINUSE」
端口 7800 被占用。解决方法：
```bash
netstat -ano | findstr :7800
taskkill /F /PID <上面显示的PID>
```

### 3. Excel 导入报错「没有数据可导入」
检查 Excel 文件：
- 第一行必须是表头
- 至少有一行数据
- 文件格式是 .xlsx 或 .xls（不是 .csv）

### 4. 手机连不上服务器
- 检查手机和电脑是否同一 WiFi
- 检查 Windows 防火墙是否阻止了 7800 端口
- 在 cmd 里测试：`telnet 服务器IP 7800`

### 5. 数据库文件损坏
删除 `server/data/brc.db`，重启服务器会自动创建新数据库（数据会丢失，提前备份）。

### 6. 数据能迁到 GGCE 吗？
可以。先在系统设置里把「数据源模式」切换到 GGCE，填好 GGCE Server URL，BRC Nexus 会自动调用 GGCE 的 API 读取数据。但 GGCE 需要先单独部署（Java + SQL Server/MySQL）。

## 九、技术架构（进阶）

- **服务器**：Node.js + Fastify + sql.js（纯 JS SQLite）
- **数据库文件**：`server/data/brc.db`
- **前端**：React 18 + TypeScript + Vite + Tailwind CSS
- **打印代理**：Electron + WebSocket + 热敏打印机驱动
- **部署模式**：单机服务器 + 局域网多设备浏览器访问

数据流向：
```
Excel 文件 → [服务器解析] → sql.js 数据库 (brc.db)
                                ↓
浏览器访问 ←→ API (/api/...) ←→ 服务器
                                ↓
                  WebSocket → 打印代理 → 热敏打印机
                                ↑
   标签模板 → 设计器渲染 labelsHtml（所见即所得，兜底走旧版文本+二维码）
```

## 十二、标签设计完全指南（v2.1 新增）

设计器已全面对标 LabelNova，功能包括：**12 种元素、内容片段绑定、表格合并、对齐分布、层级编组、撤销重做、数据源导入、打印预览、PDF 导出**。

### 1. 进入设计器

登录后点击左侧 **「标签设计」**。

- 首次使用会弹出 **新建标签向导**：选择 **卷式**（热敏标签卷，可设每卷列数、列间距）或 **纸张**（如 A4/A3/A5 平版，可设行数、列数、边距、间距）
- **随时可改**：点击画布空白处（不选中任何元素），右侧属性面板出现 **「纸张 / 打印排版」** 区块，可随时在卷式 / 纸张之间切换、换纸张预设（A3/A4/A5/B5/自定义）、调边距间距，行列数自动重算
- 右侧 **模板列表** 可切换、保存、删除模板；最近打开的模板会记忆在本地
- 工具栏右侧可 **保存**（Ctrl+S）、**打印**（Ctrl+P）、**导出 PDF**

### 2. 画布操作

| 操作 | 方式 |
|---|---|
| 缩放 | 滚轮 / Ctrl+滚轮 / 工具栏 +、- / Ctrl+0 适应窗口 |
| 平移 | 按住鼠标中键拖动，或**按住空格键 + 左键拖动** |
| 选择 | 单击元素；按住 Ctrl 点击多选；**框选**（空白处拖出矩形框） |
| 移动 | 拖动元素；方向键微调（1mm，Shift+方向键 = 10mm） |
| 旋转 | 拖动元素上的旋转手柄（**按住 Shift 吸附 15° 整数倍**） |
| 翻转 / 快捷旋转 | 工具栏「水平翻转 / 垂直翻转 / ±45° 旋转」按钮 |
| 删除 | Delete / Backspace，或右键 → 删除 |

画布上方和左侧配有**毫米级高精度标尺**（放大后显示 1mm 细刻度），方便精准定位。画布以**真实毫米**为单位显示，1mm 就是 1mm，所见即所得。

### 3. 十二种元素

工具栏依次为（悬停可看提示）：

1. **静态文本** — 固定文字，可设加粗、对齐、颜色、反色
2. **动态字段** — 绑定数据列（如 cccapNo、name），可拼接多个片段
3. **多行段落** — 自动换行的长文本，可设垂直对齐（顶部/居中/底部）
4. **日期** — 打印日期，格式任意（YYYY年MM月DD日 / YYMMDD…），可偏移天数
5. **表格** — 行列可调、**支持合并单元格**（行/列合并、拆分）、边框颜色、行高列宽
6. **条码** — 一维码 Code128 / EAN13 / …（右侧属性可选码制、条码下方文字）
7. **二维码** — QR Code，可设纠错级别 L/M/Q/H
8. **矩形** — 圆角、边框粗细、背景填充色
9. **圆形** — 描边、填充
10. **直线** — 粗细、颜色、虚线
11. **图片** — 上传 PNG/JPG
12. **图标** — 内置常用图标（星标、标签等），可改颜色

### 4. 内容绑定（片段系统，LabelNova 风格）

选中「动态字段 / 条码 / 二维码 / 段落」后，属性面板的 **内容片段** 区可自由拼接：

- **文本** — 写死的字，如「编号:」
- **字段** — 数据列，如 cccapNo（也可直接在数据源表格里点列名自动插入）
- **变量** — 全局变量：内置操作员/培养基等；点工具栏 **「变量」按钮** 可新增自定义变量（设默认值），改一次全部同步
- **日期** — 带格式和偏移
- **序列号** — 起始值、步长、每个号重复次数、最小位数（如 3 → 001）、递增/递减

> 高级用法：元素可「赋值给变量」（assignVariable），把解析结果存成全局变量供后面元素引用 —— 适合「先算序列号、后打印」的复杂模板。

序列号在**分段/跳页打印**时保持连续（按整份清单的绝对行号计算）。

### 5. 对齐、分布、层级、编组

选中 ≥1 个元素后，工具栏出现：

- **对齐**：左对齐 / 水平居中 / 右对齐 / 顶对齐 / 垂直居中 / 底对齐
  - 多选时以**第一个选中元素**为基准
  - **只选 1 个元素时相对整个画布对齐**（如绝对居中于标签纸）
- **分布**：水平等距 / 垂直等距
- **层级**：上移一层 / 下移一层 / 置顶 / 置底
- **编组**（Ctrl+G）/ **取消编组**（Ctrl+Shift+G）— 编组后可整体移动
- **复制**（Ctrl+D）— 复制选中元素

### 6. 数据源

设计器左下角可导入 **Excel / CSV**（浏览器本地解析，无需上传服务器），或一键载入 **系统数据**（系统设置里导入的种质数据）。导入后：

- 下拉切换预览行，实时查看不同记录的标签效果
- 点击列名可把该列作为动态字段插入选中元素；勾选 **「自动加项名」** 后插入的内容自带前缀（如 `姓名: [姓名]`）
- Excel 有**多个工作表（Sheet）**时可下拉切换
- 图片/背景图上传时自动轻量压缩，防止模板过大导致打印卡顿
- 打印时使用此数据源（或由调用方如「组培继代」传入数据）

### 7. 撤销 / 重做

Ctrl+Z 撤销 / Ctrl+Y（或 Ctrl+Shift+Z）重做。连续拖动或输入会合并为一步，避免撤销刷屏。

## 十五、种质资源与自定义性状系统（v2.2 新增）

### 1. 种质资源页面

左侧导航「**种质资源**」进入，可：
- 搜索品种编号 / 名称 / 物种
- 点击列表中的一行，右侧滑出「种质详情」，字段按分类分组展示
- 「新建种质」按钮创建新品种：填写编号（primaryId，必填）、名称、物种、产地，并可勾选性状值
- 管理员可删除种质；普通用户可编辑

### 2. 什么是「性状」？

种质数据除了编号、名称、物种、产地等基本信息外，还包含大量**测试性状**，例如：
- 形态：块茎形状、块茎皮色、花形、茎翼形状
- 抗性：晚疫病抗性、PVY 病毒抗性、青枯病抗性、抗旱性
- 品质：干物质含量、蛋白含量、维生素C、铁锌含量
- 等

系统**预置了 70 个 CIP 标准性状**（来源于 CIP genebank 数据与 potato-catalogue 分类体系），并按 11 个分类组织：核心收集品、形态特征、气候适应、品质与加工、病毒抗性、真菌/细菌抗性、非生物胁迫、线虫抗性、虫害抗性、营养成分、其他。

### 3. 自定义性状（满足个性化测试）

由于未来种质数据还会包含预置字典之外的自定义测试项，系统提供**自定义性状管理**：

1. 进入「种质资源」→ 点击右上角「**管理性状**」
2. 弹窗按分类列出全部性状；「系统预置」为灰色标签，不可删除；「自定义」为黄色标签
3. 点「**新增性状**」，填写：
   - 性状代码（英文大写，如 `MY_TRAIT`，唯一）
   - 中文名称 / 英文名称
   - 分类（可从现有 11 类中选择）
   - 值类型：**文本 / 数字 / 等级值**
     - 选「等级值」时，可定义等级表：每行一条，格式 `数值=描述`，例如
       ```
       1=很差
       5=中等
       9=极好
       ```
   - 单位（如 `%`、`天`、`mg/100g`），仅文本/数字类型需要
4. 保存后，新建或编辑种质时即可选择该性状并填值
5. 系统预置的性状也可编辑（补充分级描述等），但代码不可修改

### 4. 种质详情中的性状展示

- 详情面板按分类分组显示已填写的性状，显示**友好中文名**而非代码
- 等级值性状填了数字时，会显示**数值 + 描述**，例如 `5 · 中等`（与 CIP catalogue 的 `7 = Long-oblong` 风格一致）
- 编辑模式下所有已注册性状（含未填写的）都会列出，空分类可折叠；填好后保存即可

## 十六、性状检索（v2.3 新增）

种质页内嵌「**性状检索**」面板，解决"性状藏得太深、不可检索"的问题——**按一个或多个性状跨种质组合查询**，所有条件为 AND 关系。

1. 进入「种质资源」→ 列表上方点击「**性状检索**」展开面板
2. 每个条件一行：**性状 ▾ + 算子 ▾ + 值**
   - 性状按分类分组，选数值型性状后算子自动切换为 `大于 / 大于等于 / 小于 / 小于等于 / 等于 / 不等于 / 为空 / 不为空`
   - 文本型：`包含 / 等于 / 不等于 / 为空 / 不为空`
   - 等级值型：下拉直接选等级（如 `5 · 中等`）
   - 值输入框带**历史值下拉**（该性状在现有种质中的去重值，可直接点选）
3. 点「＋条件」可叠加多个条件（AND 连接）；「查询」后下方列表即命中结果，右上角显示「命中 N 条」；「清除」回到全部
4. 举例：`干物质含量 大于 22` **且** `蛋白质含量 不为空` → 返回同时满足两个条件的种质

> 说明：性状检索只针对已登记的性状代码（管理性状里注册过的），数值按实际数值比较而非文本。

## 十七、AI 助手接入（v2.3 新增；v2.7 起角色化令牌）

系统预留了两条 AI 通道，AI 助手（Claude Desktop / workbuddy / Cursor / Claude Code 等）可通过 MCP 或直连 REST 网关查询种质、性状、库存、操作记录等**只读数据**，无需登录界面。

### 1. 获取 AI Token

「系统设置」→「**AI 接入**」区块 → 点「显示」查看管理员默认 Token；「重置」可轮换。Token 与用户登录密码无关，独立鉴权。

**v2.7 起支持角色化作用域令牌**（强烈推荐）：同一区块下方「**作用域令牌管理**」中，管理员可为不同用户创建绑定角色的 Token（admin / approver / operator / regulator / external）。每个 Token 只能调用该角色作用域内的 AI 工具，**服务端强制校验**——普通用户 Token 永远无法获得管理权限（登录日志、系统消息、导出、令牌管理等均被拒绝）。令牌明文仅创建时显示一次，请立即保存；可随时启用 / 吊销。

> 权限矩阵与硬性规则详见仓库内 `skills/brc-nexus/SKILL.md`。

### 2. 方式一：MCP（推荐给桌面 AI）

```json
{
  "mcpServers": {
    "brc": {
      "command": "node",
      "args": ["C:\\Users\\Lenovo\\brc-helper-v2\\brc-mcp-server\\src\\index.js"],
      "env": {
        "BRC_URL": "http://localhost:7800",
        "BRC_TOKEN": "<你的 AI Token>",
        "BRC_TOKEN_NAME": "operator-张三"
      }
    }
  }
}
```

MCP Server 文件在 `brc-mcp-server/`，`npm install` 后即可使用；详细接入说明见 `brc-mcp-server/README-接入说明.md`。v2.7 起，MCP Server 启动时会向服务端查询当前 Token 的作用域，**只注册该作用域内的工具**，越权的工具不会暴露。

### 3. 方式二：直连 REST 网关

```bash
curl -X POST http://localhost:7800/api/ai/query \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <AI_TOKEN>" \
  -d '{"tool":"search_accessions","params":{"q":"CIP-10"}}'
```

可用工具按 Token 角色而定（admin 最多）：`search_accessions`、`query_traits`、`get_accession`、`get_inventory`、`get_operation_records`、`get_cryo_records`、`get_trait_definitions`、`export_accessions`（approver/admin）、`get_freezer_status`、`get_stats`、`get_login_log` / `get_messages`（仅 admin）。全部只读，不会修改数据；越权调用返回 403。

## 二十、种质引进审批（v2.3 新增）

| 组培人员（operator） | 今日任务（被派给我的在途工单，按 逾期→优先级→截止 排序）、我的待办、快速报工 |
| 审批人员（approver） | 审批队列（待审批的引进 / 分发申请）、我的待办 |

### 32.2 工单派单 / 排单（任务管理）

- 左侧「**任务管理**」（管理员 / 组培人员 / 监管方可见）。管理员点「新建工单」：填写标题、描述，**多选指派组培操作员**，**选择具体种质编号**（可搜索多选），选择用途（扩繁 / 保存 / 分发，带出对应步骤链预览与计划天数），设置目标数量、优先级、截止日期。

- 点击工单卡片打开**详情抽屉**：基本信息、步骤链、**报工时间线**（进度 / 受阻 / 完成，含数量、内容、步骤、照片）、关联操作记录（报工带步骤时同步写入操作记录留痕）。

### 32.3 个人清单（我的清单）

- 左侧「**我的清单**」对所有登录用户开放，含两个页签：
  - **我的清单**：手动建立的工作清单（标题 / 备注 / 截止 / 优先级），可勾选完成、编辑、删除。
  - **派给我的任务**：管理员下发给我的工单（只读列表，含状态徽章 / 进度条 / 逾期标记），可直接**快捷报工**。

### 32.4 逾期扫描

服务器每 60 秒自动扫描未完成且超过截止日期（宽限天数见「系统参数配置 → 工单 → 工单逾期提醒宽限天数」，默认 1 天）的工单，向管理员与相关操作员发送逾期提醒消息。

     - 只读语句（SELECT / PRAGMA / EXPLAIN）直接放行；

## 五十三、找种质向导（v2.10 新增）

**面向申请者的问卷式检索**：不同于种质管理页的管理视角搜索，「找种质」让不懂性状代码的人按"我想要什么材料"来找到种质，选中后一键生成分发申请。所有登录用户可用（导航「找种质」）。

**四步流程**：

1. **挑性状**：按性状类别分组勾选（卡片带 ⓘ 说明卡）；
2. **定标准**：为每个性状可选设置筛选条件——等级性状给下拉（带"值 · 含义"），数字性状给大于/小于等区间，文本给包含匹配；**留空 = 只展示该列、不筛选**；
3. **看结果**：种质 × 性状对比矩阵 + **库存列**（"有货 N" 绿标 / "需扩繁" 黄标——有货表示可直接分发，需扩繁表示库存为零仍可申请、走组培扩繁流程）；点击行选中，计数器显示 `已选 n / 上限 35`；支持加载更多；
4. **提交申请**：填写申请方/单位/用途/材料类型/期限（份数自动=已选数），提交后生成一份**分发申请**（来源标记 `wizard`），进入现有审批流——管理员审批时可直接看到申请者勾选的种质清单与筛选条件，作为审核上下文。

**上限规则**：一次申请最多 **35 个编号**（可在 系统设置 → 参数 `dist.max_accessions` 调整）。**该上限由服务端强制**（API 直调同样被拦，返回 `TOO_MANY_ACCESSIONS`），前端只是友好提示。

**技术说明**：检索复用现有内核 `POST /api/accessions/query`（v2.10 起支持空条件=浏览全部，且每行附带 `stockTotal/stockForms` 库存汇总）；`dist_request` 新增 `accessions_json`（选中的种质清单 id/code/name）与 `source`（manual/wizard）字段，旧数据自动兼容（source=manual、清单为空）。

**未涉及**：此向导暂不支持完全匿名公开访问（需登录）；外部用户公网/VPN 接入仍按第五十一节备忘执行，开通后此向导对 external 自动可用。

## 五十四、MCP 接入：让申请者用自己的 AI Agent 找种质（v2.11 新增）

**这是什么**：系统现在暴露一个标准 **MCP (Model Context Protocol) 端点** `POST /mcp`，外部申请者可以用自己的 AI 助手（如 Claude）通过自然语言找种质、查库存、提交分发申请——自然语言到筛选条件的翻译发生在**申请者自己的 agent 里**，服务端不跑任何大模型。

**四个工具**：

| 工具 | 作用 |
|---|---|
| `search_germplasm` | 按性状条件检索种质（返回护照+性状+库存，字段白名单，绝无敏感数据） |
| `get_accession` | 查单个种质详情（护照、全部性状、库存、基因组学记录） |
| `submit_distribution_request` | 提交分发申请（**服务端强制 ≤35 个编号**、黑名单检查、来源标记 `mcp`） |
| `get_my_requests` | 查询本令牌提交的申请与审批进度 |

**接入三步**：

1. **管理员发令牌**：系统设置 → AI 令牌 → 新建（以申请者命名，如 `zhang-san`；明文只显示一次）。该令牌同时用于 MCP。
2. **申请者配置 agent**：
   ```bash
   claude mcp add --transport http cccap-brc http://<主机>:7800/mcp      --header "Authorization: Bearer <令牌>"
   ```
   或把 `docs/mcp-skill/mcp-config.example.json` 改好后放入 agent 配置。
3. **安装交互技能（可选但推荐）**：把 `docs/mcp-skill/SKILL.md` 安装到申请者的 Claude（复制到 `~/.claude/skills/cccap-brc/`）。技能里写死了交互策略：**永不选全部>35 个、引导继续筛选而非放弃、提交前必须向用户确认清单、始终展示库存状态**。

**安全边界**：

- 鉴权：Bearer 令牌 → sha256 → `ai_token` 表（可随时停用）；无效/停用 → 401。
- 限流：`mcp.rate_limit_per_min`（默认 120 次/分钟/令牌），超限 429。
- 审计：每次工具调用写 `audit_log`（action=`MCP_CALL`，含令牌名与参数摘要）。
- 字段白名单：只返回护照+性状+库存；`data_json` 原文、用户表、审计表等一律不可达。
- 申请流：MCP 提交的申请与手工/向导完全同构（`source='mcp'`、`created_by=令牌名`），走同一审批流，35 上限与黑名单同样生效。
- 网络路径：当前面向内网；公网/VPN 开通仍按第五十一节备忘执行，端点零改动。

## 六十五、Excel 导入修复：IMPORT 按钮静默无效（v2.19 期间用户报障，2026-11-27）

**由来**：用户在新机上测试，Setup 独立模式上传 Excel（12 行）后点 **IMPORT 12 RECORDS 无任何提示、种质资源页无数据**。排查出**三层叠加缺陷**，后两层自 v2.7（sql.js→node:sqlite）迁移后就存在，但被第一层挡住从未走到：
1. **上传契约断裂**（直接原因）：`/api/excel/upload` 只回传 `{totalRows, headers, preview(前5行), detected}`，**不含 `rows`**；前端 `setExcelRows(res.rows || [])` → `excelRows` 恒为空数组 → `handleImport` 首行 `if (!excelRows.length) return` **静默返回**——不发请求、不报错、不提示，按钮永远无效。
2. **导入服务 API 失配**：`excel-import.js` 调 `db.transaction(fn)`（better-sqlite3 的 API），node:sqlite 的 `DatabaseSync` 没有此方法 → 就算数据送达也会 500 `db.transaction is not a function`。项目封装的事务是 connection.js 的模块级 `tx(fn)`。
3. **连带 UX 缺陷**：结果横幅 `importResult` 渲染在预览卡内部，而成功路径 `setExcelPreview(null)` 会卸载整卡——即使前两层修好，成功提示也永远看不见。

**做了什么**：① `routes/excel.js` upload 响应补回完整 `rows`；② `excel-import.js` 改走 `tx()` 包装（抛错自动回滚）；③ `Setup.tsx` 空数据时给红字提示（不再静默）+ 结果横幅移出预览卡（成功绿/失败红）+ Cancel 清横幅；④ `p0.test.mjs` 新增第 12 项契约测试（upload 必须回传完整 rows + import 入库 + skip 模式幂等）。

**验证**：`node --test server/test/p0.test.mjs` **12/12 全绿**；真实 UI 端到端（隔离实例 7811 + 临时库 + 真实 `测试数据-种质.xlsx`）：登录 → Setup 上传 → Detected 12 rows → IMPORT → 横幅**「导入完成: 12 条新增, 0 条更新, 0 条跳过」**→ 种质资源页**共 12 条** → API 确认 `total: 12`（CIP-001~005 / 101~105 / 201~202）。前端 `tsc` 通过、已重建 `client/dist`（server 实时读盘，浏览器刷新即生效）。

**已知限制（明确不做）**：`/api/excel/import` 走 JSON body，Fastify 默认 bodyLimit 1 MiB，超大 Excel（数万行）会 413 报「请求失败」；要支撑大文件应让 import 直接收 multipart 由服务端解析，本次不做（保持最小改动）。`Setup.tsx`「使用内置 sql.js 数据库」的过期文案未动（踩坑点 2，另行处理）。

## 六十六、Excel 导入去重根因修复：按 primary_id 匹配，不再把编号当内部 id（v2.19 期间用户报障，2026-11-27）

**由来**：上节修复后用户实测导入成功，但查库发现**同一编号出现两行**：导入把编号（如 `CIP-001`）直接写进 `accession.id`，而系统约定（界面/接口建行，`routes/accessions.js`）是 `id = UUID`、编号存 `primary_id`。先在界面建了种质、再用 Excel 导入同编号时两边撞不上 → **复制出一行**。实测当时库里 12 条界面老数据 × 13 行导入（含用户手加的 CIP-203 测试行）= 12 对重复。且用户因无提示点了两次 IMPORT（第二次 replace 对第一次的行原地更新，未再翻倍）。

**做了什么**：`excel-import.js` 循环改为先按 `primary_id` 查已有行——命中则**沿用其内部 id 做 upsert（更新原行）**，未命中则 `id = uuidv4()` 新建（与系统约定一致）；顺带修正 replace 模式计数（原先一律计 `inserted`，现在准确区分新增/更新，绿横幅数字变真了）。测试：第 12 项契约测试改按 `primary_id` 断言并校验新行 id 为 UUID；新增第 13 项去重测试——`POST /api/accessions` 界面同款建行 → 同编号 replace 导入 → 断言 `updated=1 / inserted=1`、行数不增、原行 id 不变、skip 模式对界面行生效。

**验证**：`node --test server/test/p0.test.mjs` **13/13 全绿**；重启真实服务（7800）后真库端到端：导入一行已存在编号 CIP-001 → `{"inserted":0,"updated":1,"skipped":0}`，种质总数 **13 → 13**（修复前会是 14）。

**备注**：当时那 12 对重复已随用户「从头试」的清库操作移除（清前整库备份在 `server/data/backups/pre-clean-accession-2026-11-27-01-47-18.db`）。今后从任何来源恢复老数据后再导入，都按编号更新原行，不会复发。
